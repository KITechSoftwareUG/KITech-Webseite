# Schema E — Quiz-Funnel

**Basis:** Interaktive Qualifizierung mit personalisiertem Ergebnis. Einzige Schema hier,
das nicht rein linear/statisch ist — die Mechanik selbst unterscheidet sich, nicht nur
die Beat-Reihenfolge. Deckt sich mit dem bereits in `funnels/CLAUDE.md` dokumentierten
"Quiz/Rechner-Funnel"-Muster (`/` → `/start` → `/offer` → `/book` → `/thank-you`).

## Beat-/Seiten-Reihenfolge

### 1. Hook (`/`)
Bold-Headline wie in Schema A, aber das Versprechen zielt auf das Quiz-Ergebnis selbst
("Finde in 2 Minuten heraus, ob..."), nicht auf das Endangebot. CTA führt zum Quiz, nicht
zu einem Call.

### 2. Interaktive Qualifizierung (`/start`)
Quiz/Rechner/Demo. Jede Frage muss selbst schon Reziprozität liefern (der Leser lernt
etwas über die eigene Situation, während er antwortet) — sonst ist es nur eine Hürde vor
dem Ergebnis, keine Wertschöpfung.

### 3. Personalisiertes Ergebnis (`/offer`)
Das Ergebnis muss so konkret wirken, dass es nicht wie eine von 3 Standard-Antworten
aussieht, selbst wenn es technisch eine ist — Formulierung mit den tatsächlich
eingegebenen Werten/Antworten des Nutzers, nicht generisch.

### 4. CTA (`/book`)
Erst hier der Call/Booking-CTA — nach dem Ergebnis, nie davor.

### 5. Danke (`/thank-you`)
Bestätigung, keine neue Verkaufsbotschaft.

## Verhältnis zu Testimonials/Bewertungen

Können auf `/offer` ergänzend neben dem personalisierten Ergebnis stehen (Social Proof,
dass die Empfehlung, die der Nutzer gerade bekommen hat, bei anderen funktioniert hat) —
aber nie vor dem Ergebnis selbst, das würde die Personalisierung entwerten.
